OpenClaw 完全新手指南

从零开始，把 Claude 变成你的私人 AI 助手，接入 Telegram / 飞书 / Discord，7×24 小时帮你干活。

⏱ 阅读约 20 分钟 🖥 macOS / Linux 🤖 Claude API 📱 多渠道接入 🛠 可扩展技能

🤔 OpenClaw 是什么？

想象一下：你在 Telegram 上随手发一句话，就能让 AI 帮你查邮件、读文件、搜索资料、写代码、发消息……
这就是 OpenClaw 做的事情。

OpenClaw 是一个自托管的 AI 助手框架，你在自己的电脑/服务器上运行， 通过 Claude、GPT 等大语言模型驱动，然后接入你常用的聊天软件（Telegram、飞书、Discord 等）。

🔒

完全私有

运行在你自己的机器上，数据不经过第三方服务器

🧩

可扩展技能

通过 Skills 系统扩展能力：查邮件、控音乐、搜网页……

💬

多渠道接入

Telegram / 飞书 / Discord / WhatsApp / iMessage 均可

🧠

持久记忆

AI 有长期记忆，了解你的习惯和偏好

⏰

定时任务

设置 Cron，让 AI 在固定时间自动做事

🤖

多 Agent

可以配置多个助手，分别处理不同渠道和任务

📐 系统架构（简版）

不需要深入理解，但知道这几个概念会帮助你更快上手：

组件 是什么 类比
Gateway OpenClaw 的核心服务，在后台运行 大脑 + 神经系统
Agent AI 助手实例（你可以有多个） 有个性的具体助手
Channel 接入的聊天渠道（Telegram/飞书等） 助手的"嘴巴"和"耳朵"
Skills 扩展功能的插件（邮件/日历/音乐等） 助手学的技能
Workspace AI 的工作目录（文件、记忆都在这里） 助手的桌面 + 笔记本
💡

你只需要在自己的电脑上安装 OpenClaw，它会在后台静默运行。你通过 Telegram/飞书等聊天软件和 AI 交互，AI 可以访问你电脑上的文件、执行命令、调用各种服务。

macOS 12+ 或 Linux (Ubuntu 20.04+)

Node.js 18 或以上版本
推荐用 nvm 管理版本

🔑 Claude API Key

需要 Anthropic 账号
可在 console.anthropic.com 获取

能访问 Anthropic API

检查你的 Node.js 版本

打开终端（Terminal），输入：

node --version
# 应该显示 v18.x.x 或更高
# 如果没安装，参考下方安装方法

如果没有 Node.js，用这个方法安装（推荐）：

# 安装 nvm（Node 版本管理器）
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.0/install.sh | bash

# 重新打开终端后，安装 Node.js
nvm install 20
nvm use 20
nvm alias default 20

⚙️ 第一步：安装 OpenClaw

打开终端，一行命令搞定：

npm install -g openclaw
ℹ️

安装完成后，openclaw 命令就全局可用了。如果提示权限错误，试试 sudo npm install -g openclaw（macOS 用户推荐用 nvm 避免权限问题）。

验证安装成功

openclaw --version
# 显示版本号就代表安装成功，例如：OpenClaw 2026.3.13

创建工作区目录

AI 需要一个"家"，用来存放记忆、工具和配置：

# 创建工作区（你可以改成任意位置）
mkdir -p ~/my-ai-workspace
cd ~/my-ai-workspace

🚀 第二步：初始化与启动 Gateway

运行交互式向导

OpenClaw 提供了一个引导式的初始配置向导，跟着提示走就行：

openclaw configure

向导会问你一些问题，按下面的参考回答：

问题建议回答
Workspace directory输入你刚创建的路径，如 /Users/你的名字/my-ai-workspace
AI provider选 Anthropic (Claude)
API Key粘贴你的 Claude API Key（下一章节讲如何获取）
Default model推荐 claude-sonnet-4-6（性价比最高）
Agent name给你的 AI 起个名字，如 Aria、Nova

启动 Gateway 服务

Gateway 是 OpenClaw 的核心后台服务，需要保持运行：

# 启动 Gateway（首次启动）
openclaw gateway start

# 查看运行状态
openclaw gateway status

# 如果需要重启
openclaw gateway restart
✅

看到 Gateway is running 就代表成功了！Gateway 会在后台静默运行，关闭终端不影响。

让 Gateway 开机自启（可选）

推荐设置，这样重启电脑后不需要手动启动：

# macOS：注册为 launchd 服务
openclaw gateway install

# Linux：注册为 systemd 服务
openclaw gateway install --systemd

🤖 第三步：获取并配置 Claude API Key

申请 Anthropic API Key

  1. 访问 Anthropic Console

    打开浏览器，访问 console.anthropic.com，注册或登录账号。

    ⚠️

    国内用户需要代理才能访问。建议注册时使用非中国大陆的手机号。

  2. 创建 API Key

    登录后，点击左侧菜单的 「API Keys」，然后点 「Create Key」。

    给 Key 起个名字（如 my-openclaw），然后点创建。

  3. 复制 Key（只显示一次！）

    Key 会以 sk-ant-api03-... 开头。立刻复制保存，关掉页面就看不到了。

  4. 充值（建议先充 $5~$20）

    在 Console 的 Billing 页面充值。Claude Sonnet 的费用约为每 100 万 token 约 $3，日常使用非常省。

将 API Key 配置到 OpenClaw

# 方法一：通过命令行配置（推荐）
openclaw config set auth.anthropic.apiKey "sk-ant-api03-你的key"

# 方法二：重新运行向导
openclaw configure

# 方法三：直接编辑配置文件
# 配置文件在：~/.openclaw/openclaw.json

验证 API 连通性

# 运行健康检查
openclaw doctor

# 测试 AI 对话（不需要聊天软件）
openclaw agent "你好，请介绍一下你自己"
✅

如果 openclaw doctor 显示所有检查通过，或者 openclaw agent 命令返回了 AI 的回答，说明 Claude 已成功接入！

选择合适的模型

模型特点适合场景价格（每百万 token）
claude-sonnet-4-6 ⭐ 推荐 日常全能，速度快，性价比高 输入 $3 / 输出 $15
claude-opus-4-6 最强智能 复杂推理、深度分析、研究报告 输入 $15 / 输出 $75
claude-haiku-3-5 最快最便宜 简单问答、高频调用 输入 $0.25 / 输出 $1.25 
# 设置默认模型
openclaw config set agents.defaults.model.primary "anthropic/claude-sonnet-4-6"

📡 第四步：连接聊天渠道

AI 配置好了，现在要让它"出现"在你的聊天软件里。

🚀 接入 Telegram（推荐首选）

Telegram 是最容易配置的渠道，功能也最完整。

  1. 创建 Telegram Bot

    在 Telegram 中搜索 @BotFather，发送 /newbot。

    按提示填写：

    • Bot 显示名称：比如 My AI Assistant
    • Bot 用户名（必须以 bot 结尾）：比如 my_ai_helper_bot

    BotFather 会返回一个 Token，格式类似 7123456789:AAH...，复制保存。

  2. 将 Token 配置到 OpenClaw

    # 添加 Telegram 渠道
openclaw channels add telegram

# 按提示粘贴你的 Bot Token

    或者手动配置（编辑 ~/.openclaw/openclaw.json）：

    {
  "channels": {
    "telegram": {
      "enabled": true,
      "token": "7123456789:AAH你的token"
    }
  }
}

  3. 重启 Gateway 并测试

    openclaw gateway restart

    在 Telegram 中找到你的 Bot，发送 /start 或任意一句话，AI 应该会回复！

💡

安全提示：默认情况下，任何知道 Bot 用户名的人都可以和你的 AI 说话。建议在配置中设置白名单，只允许你自己的账号：

# 获取你的 Telegram User ID（发消息给 @userinfobot）
# 然后配置白名单
openclaw config set channels.telegram.allowedUsers '["你的UserID"]'

🐦 接入飞书

飞书需要创建一个企业自建应用，步骤多一点但并不复杂。

  1. 创建飞书自建应用

    访问 open.feishu.cn，登录后进入「开发者后台」→「创建企业自建应用」。

    记录下 App ID 和 App Secret。

  2. 配置应用权限

    在应用管理页面，进入「权限管理」，开通以下权限：

    • im:message — 接收/发送消息
    • im:message:send_as_bot — Bot 发消息
    • im:resource — 图片/文件

  3. 配置事件订阅

    在「事件订阅」中，填入 OpenClaw 的 Webhook 地址：

    http://你的服务器地址:18789/feishu/webhook
    ⚠️

    如果是本地电脑，飞书无法直接访问，需要用 内网穿透 工具（如 Cloudflare Tunnel、ngrok）或部署到有公网 IP 的服务器。

  4. 配置到 OpenClaw

    openclaw channels add feishu
# 按提示输入 App ID 和 App Secret

🎮 接入 Discord

  1. 创建 Discord Application

    访问 discord.com/developers/applications，点「New Application」。

    进入应用后，点左侧「Bot」→「Add Bot」，然后点「Reset Token」获取 Bot Token。

  2. 邀请 Bot 到你的服务器

    在「OAuth2」→「URL Generator」中，勾选 bot 权限，以及：

    • Send Messages
    • Read Message History
    • Use Slash Commands

    复制生成的链接，在浏览器打开，邀请 Bot 到你的服务器。

  3. 配置到 OpenClaw

    openclaw channels add discord
# 粘贴你的 Bot Token

🛠 安装技能 (Skills)

Skills 是 OpenClaw 的扩展系统。每个 Skill 给 AI 增加一种新能力。 类似手机 App，按需安装，不用就不装。

浏览和安装技能

# 列出所有已安装的技能
openclaw skills list

# 搜索可用技能（从 ClaWhub 社区）
openclaw skills search 邮件

# 安装技能
openclaw skills install himalaya   # 邮件管理
openclaw skills install spotify-player  # Spotify 控制
openclaw skills install weather    # 天气查询

# 更新所有技能
openclaw skills update

推荐的入门技能

📧 himalaya IMAP/SMTP 邮件管理
🌤️ weather 天气查询预报
📅 apple-reminders Apple 提醒事项
🎵 spotify-player Spotify 播放控制
📝 bear-notes Bear 笔记管理
🐙 github GitHub 操作
🔍 summarize 网页/视频总结
🎤 voice-call 语音通话
💻 coding-agent 代码生成与修改
📸 camsnap 摄像头抓图

技能安装后在哪里？

技能安装后存放在 ~/.openclaw/skills/ 目录下，每个技能都有一个 SKILL.md 文件描述其用法。AI 会自动识别并学会使用它们。

💡

安装技能后，直接用自然语言告诉 AI 你想做什么，它会自动判断用哪个技能。比如安装了 weather 技能后，你可以直接问「今天北京天气怎么样？」

手动添加技能（从社区下载）

# 也可以直接把技能文件放到技能目录
mkdir -p ~/.openclaw/skills/my-skill
# 然后在里面放 SKILL.md 文件即可

📁 工作区配置（让 AI 更了解你）

Workspace 是 AI 的"家"，里面有几个重要文件，你可以编辑它们来告诉 AI 你是谁、你希望它怎么工作。

核心文件介绍

文件用途谁来写
SOUL.mdAI 的性格、工作风格、核心原则你来定义
USER.md你的基本信息（名字、时区、偏好）你来填
AGENTS.mdAI 的行为规则、安全边界你来设置
TOOLS.md本地设备信息（SSH、摄像头等）你来记录
MEMORY.mdAI 的长期记忆（会自动更新）AI 自动维护
HEARTBEAT.md定期自动检查任务配置你来设定
memory/每日记忆日志目录AI 自动生成

USER.md 示例

# USER.md - 关于我

- **名字**: 你的名字
- **称呼**: 如何叫我（可以是昵称）
- **时区**: Asia/Shanghai
- **语言**: 主要用中文交流
- **Telegram**: @your_handle

## 偏好
- 回复要简洁直接，不喜欢废话
- 代码问题用中文解释，但代码本身用英文
- 早上不要发太多消息打扰我

SOUL.md 示例（AI 的性格）

# SOUL.md - AI 的核心性格

## 基本原则
- 直接有用，不要废话连篇
- 有自己的观点，不要一味附和
- 遇到不确定的事情，先查清楚再回答

## 工作方式
- 默认主动一点，不要总是问"需要我帮忙吗？"
- 重要操作（删除、发消息等）先确认再执行
- 出错了要告诉我，不要假装没事

## 个性
- 可以有点幽默感
- 不需要每句话结尾都加"希望对您有帮助！"

⚡ 进阶配置

配置心跳检查（Heartbeat）

Heartbeat 是 AI 的"定时自检"机制，可以让它定期主动检查重要事项。

编辑工作区里的 HEARTBEAT.md：

# HEARTBEAT.md

## 每次心跳检查（每小时一次）：

1. 检查是否有重要邮件未读
2. 查看接下来 2 小时内有没有日历事件
3. 如果快下雨了，提醒我带伞

## 每天 8 点：
- 发送今日天气 + 日程总结

## 注意：
- 深夜 23:00 - 08:00 不要发消息打扰
- 无事可报时直接跳过，不要发"没事"

配置多个 Agent

你可以配置多个 AI 助手，比如一个用 Telegram、一个接入飞书：

# 查看当前所有 Agent
openclaw agents list

# 创建新的 Agent
openclaw agents create my-second-agent

# 指定 Agent 绑定到特定渠道（编辑配置文件）
# ~/.openclaw/openclaw.json

使用 Cron 定时任务

# 查看所有定时任务
openclaw cron list

# 创建定时任务（每天 9 点执行）
openclaw cron add --schedule "0 9 * * *" --task "检查今日邮件并发送摘要"

# 删除定时任务
openclaw cron remove <任务ID>

查看日志

# 实时查看 Gateway 日志
openclaw logs

# 查看特定日志文件
cat ~/.openclaw/logs/gateway.log

备份与恢复

# 创建备份
openclaw backup create

# 查看备份列表
openclaw backup list

# 恢复备份
openclaw backup restore <备份ID>

更新 OpenClaw

# 更新到最新版本
npm update -g openclaw

# 或者
openclaw gateway restart  # Gateway 会自动检查更新

💥 真实踩坑记录

以下是实际使用中遇到的坑，很多初次部署都会中招，提前看完能省几小时。

🔴 坑 1：代理环境变量污染 Node.js（最常见！）

现象：AI 能启动，但 Claude API 调用一直报网络错误，或者内网服务莫名其妙被代理转发。

根因：Mac 或 Linux 上设置了系统代理（Clash / V2Ray 等），Node.js 的 fetch 会自动走代理，但某些代理软件会拦截 API 调用。

解法：

# 启动 Gateway 前，先临时清除代理环境变量
unset ALL_PROXY HTTP_PROXY HTTPS_PROXY http_proxy https_proxy
openclaw gateway restart

# 或者写进启动脚本里，永久生效

💡 如果你想让 Claude API 走代理，在 ~/.openclaw/openclaw.json 里单独配置代理地址，而不是依赖系统环境变量。

🔴 坑 2：大文件操作导致 AI 陷入死循环

现象：让 AI 写一个很长的文件，结果它一直在"思考"、发重复消息，甚至把整个文件内容塞进回复里刷屏。

根因：AI 的 write 工具在写入超大文件（>5000字）时，会把内容塞进模型 token 输出，撑爆 context window，触发 compaction，然后 AI 重新启动重复执行。

解法：大文件必须用 shell 写，不要用 AI 自带的 write 工具。

# 正确做法：让 AI 通过 exec 用 shell 命令写文件
cat > /path/to/bigfile.txt << 'EOF'
...文件内容...
EOF

# 或者让 AI 分块写入
# 错误做法：AI 直接 write 10000 字的文件 → 大概率出问题

🟡 坑 3：Gateway restart 会断所有连接

现象：执行 openclaw gateway restart 后，Telegram/飞书 等频道的 AI 连接断开，几秒到几十秒内无法回复。

解法：重启前先告诉 AI 让它通知你，等你做好心理准备再重启。重启后等 10-30 秒再发消息测试。

⚠️

如果你在进行重要对话，尽量避免在中途重启 Gateway。配置变更可以等对话结束后再重启。

🟡 坑 4：Cron 任务写了≠真的在跑

现象：让 AI 帮你设置定时任务（比如每天 8 点发早报），AI 说"已设置"，但实际上到点什么都没发。

根因：AI 可能只是写了配置文件，但没有验证 Gateway 是否真正加载了这个 cron。另外，cron 任务的输出默认回显到会话里，而不是发到 Telegram。

解法：

# 设置完 cron 后，先验证它真的在运行
openclaw cron list

# 手动触发一次测试
openclaw cron run <任务ID>

# 确认输出方向：是发到 Telegram 还是回显到当前会话？
# 在任务里明确指定 delivery channel

🟡 坑 5：Cloudflare Tunnel 连不上（QUIC 被代理干扰）

现象：用 Cloudflare Tunnel 做内网穿透，连接一直失败或不稳定。

根因：Mac 上的系统代理会干扰 QUIC 协议，而 cloudflared 默认用 QUIC。

解法：强制用 HTTP/2，同时清空代理环境变量。

# 启动 cloudflared 时加参数
cloudflared tunnel --protocol http2 run

# 如果用 launchd / systemd 启动，在服务配置里加环境变量
EnvironmentVariables:
  ALL_PROXY: ""
  HTTPS_PROXY: ""

🟣 坑 6：AI 心跳深夜骚扰

现象：凌晨 2 点收到 AI 发来的天气通知……

根因：Heartbeat 心跳任务没有配置时间限制，半夜也在检查然后"善意提醒"你。

解法：在 HEARTBEAT.md 里明确写静默时段。

# 在 HEARTBEAT.md 里加这一条：
## 静默规则
深夜 23:00 - 早上 08:00，无论发现什么，都不发消息。
只有极端紧急（系统崩溃、安全警报）才可以例外。

🟣 坑 7：GitHub Pages 推上去没更新（CDN 缓存）

现象：已经 git push 了，但浏览器打开还是旧版本。

原因：GitHub Pages 用 CDN 缓存，更新可能有 1-5 分钟延迟，浏览器本地也有缓存。

解法：

  • 强制刷新：Mac 上按 Cmd + Shift + R，Windows 按 Ctrl + Shift + R
  • 等 2-5 分钟后再刷，CDN 缓存通常会自动更新
  • 也可以开无痕窗口访问，排除本地缓存

🟣 坑 8：飞书渠道发文件用错方法

现象：让 AI 把文件发到飞书，收到的只是一个文件路径字符串，不是真正的文件。

根因：OpenClaw 的 message 工具的 filePath 参数在飞书渠道不生效，它只会把路径当文本发出去。

解法：需要让 AI 调用飞书原生 API 上传文件，流程是：先 POST /im/v1/files 上传获取 file_key，再通过消息接口发送。这个问题只在飞书渠道存在，Telegram 正常。

⚪ 坑 9：context 越来越长，AI 变慢变贵

现象：和 AI 聊了几天后，它的回复越来越慢，API 费用也开始增加。

原因：每次对话都会携带历史上下文，时间长了 context window 越来越大，每次调用的 token 消耗也越来越多。

解法：

  • OpenClaw 默认开启 context pruning（自动修剪），不用手动管理
  • 长任务（处理大文档、批量操作）用子进程处理，不在主对话里堆积
  • 定期重新开一个对话，而不是在一个对话里聊几十条

💡 实战小技巧

这些是用了一段时间后慢慢总结出来的使用心法，能让你的体验好很多。

🗣 怎么和 AI 说话更高效

直接说结果，不要说步骤

❌ 「先打开邮件，然后找一下今天的邮件，然后把重要的列出来」

✅ 「帮我看今天有没有重要邮件，总结一下」

AI 会自己决定怎么做，你只需要告诉它你想要什么结果。

危险操作可以让 AI 先列计划

对于删文件、发消息、修改配置这类操作，可以先说：

「先告诉我你打算怎么做，别直接执行」

AI 会先给你一个计划，你确认后再让它执行，避免误操作。

让 AI 记住你的偏好

直接说「记住：我不喜欢 xxx」或「以后帮我做 xxx 的时候，记得 yyy」，AI 会把重要偏好写进记忆文件，下次对话继续有效。

比如：「记住我用的是上海证券账户，以后查股票默认用这个」

⚙️ 配置技巧

善用 SOUL.md 定义 AI 的边界

不想让 AI 主动推送某类信息？不想它深夜打扰你？这些都可以写进 SOUL.md 或 AGENTS.md：

# 在 AGENTS.md 里写：

## 禁止主动推送
- 不要主动推荐任何产品或功能
- 不要在没有被问到的情况下评价我的决定
- 不要深夜（23:00-08:00）发消息，哪怕有定时任务触发

不同任务用不同模型

你可以在对话中临时切换模型，不需要改配置文件：

# 在聊天里直接发这个来临时切换（部分渠道支持）
/model claude-opus-4-6

# 或者告诉 AI：
「这个任务用 Opus 做，要深度分析」
「这个用 Haiku 就行，快速回答」

💡 日常聊天用 Sonnet，写研究报告/复杂推理用 Opus，批量简单任务用 Haiku。

用 Heartbeat 做轻量级监控

心跳检查不只是"没事汇报"，可以用来做有意义的监控：

# HEARTBEAT.md 示例 — 有价值的检查
## 每次心跳（每小时）：
1. 检查磁盘空间，如果不足 10GB，提醒我
2. 检查 Gateway 日志，如果有 ERROR 级别日志，告诉我
3. 检查天气，如果接下来 3 小时要下雨，提醒我带伞

## 每天 8:30：
- 今日日程 + 未完成的提醒事项

## 每周一 9:00：
- 上周的 AI 使用统计（粗略估算）

定期让 AI 整理记忆

时间长了，memory/ 目录下会积累大量日记文件。可以定期让 AI 做一次"记忆整理"：

「帮我整理一下最近 2 周的记忆日记，把重要的事情提炼到 MEMORY.md 里，删掉过时的内容」

这样 AI 的"长期记忆"会越来越精准，而不是一堆流水账。

🛡 安全与隐私

设置白名单，防止陌生人使用你的 AI

Telegram Bot 默认公开，任何知道 Bot 用户名的人都能和它说话。强烈建议配置白名单：

# 先获取你自己的 Telegram ID（发消息给 @userinfobot）
# 然后设置白名单，只允许你自己
openclaw config set channels.telegram.allowedUsers '["你的数字ID"]'

# 多人共用（比如家庭）
openclaw config set channels.telegram.allowedUsers '["ID1","ID2"]'

不要让 AI 处理真正敏感的内容

AI 的对话内容会发送到 Claude 的 API 服务器（Anthropic）。虽然 Anthropic 有隐私保护，但对于银行密码、身份证号、医疗记录这类信息，建议直接本地处理，不要让 AI 经手。

群聊里的 AI 要设置触发条件

如果把 AI 接入群聊（Discord / 飞书群等），默认它可能会回复每一条消息，影响群聊氛围。

建议配置为：只在 @提及 或 包含问句/关键词 时才回复，其余时候保持静默。

# 在 AGENTS.md 里写：
## 群聊行为规则
- 只在被 @ 或有人直接提问时回复
- 闲聊、表情包、纯分享内容：不回复
- 别人已经回答了的问题：不重复回答
- 不要主动插话，除非你能提供其他人没有的信息

🚀 进阶玩法

让 AI 自己写技能（Skills）

如果你有特殊需求，可以直接让 AI 帮你写一个自定义技能：

「帮我创建一个技能，能查询京东快递物流信息，只需要传入单号」

AI 会生成 SKILL.md 和相关脚本，放到技能目录后立即生效。

多 Agent 分工

你可以配置多个 AI 实例，各司其职：

主助手（Telegram）

日常对话、文件处理、代码帮助

工作助手（飞书）

处理工作文档、飞书通知、会议纪要

群聊机器人（Discord）

回答公开问题、提供信息查询

用子进程处理重活

遇到需要很长时间的任务（写几千行代码、处理大量数据、深度研究），可以让 AI 启动一个子进程在后台处理：

「这个任务可能要跑很久，帮我在后台处理，完成后通知我结果」

这样主对话不会被卡住，你可以继续做其他事情。

建立你自己的使用习惯

最后也是最重要的一点：OpenClaw 是高度可定制的，最终使用效果取决于你怎么"培养"它。

  • 遇到 AI 表现不好的地方，直接说「这个不对，下次应该 xxx」，AI 会记住
  • 定期更新 SOUL.md 和 USER.md，让 AI 更了解你
  • 把你的工作流程告诉 AI，它会帮你自动化重复的部分
  • 发现好的技能就安装，用不到的技能就移除，保持轻量

❓ 常见问题

Q: AI 一直没有回复，怎么办？

先检查 Gateway 是否在运行：openclaw gateway status
再检查日志是否有错误：openclaw logs
如果 API Key 有问题，会在日志里看到 401 Unauthorized。

Q: AI 回复太慢了

可以换用更快的模型：

openclaw config set agents.defaults.model.primary "anthropic/claude-haiku-3-5"

Haiku 响应速度比 Sonnet 快约 3-5 倍，但能力稍弱一些。

Q: API 费用怎么控制？

1. 在 Anthropic Console 设置每月用量上限
2. 日常使用 Sonnet 或 Haiku，只在需要深度分析时用 Opus
3. 用 openclaw models scan 查看各模型费用

Q: AI 会记住我说过的话吗？

会。OpenClaw 有持久记忆系统：
• 短期：每次对话上下文（当前会话内记住）
• 长期：重要事情会写入 MEMORY.md 和 memory/ 目录
你也可以直接说「记住：我的生日是 X 月 X 日」，AI 会主动存档。

Q: 如何让 AI 帮我执行电脑上的命令？

OpenClaw 默认允许 AI 执行 Shell 命令，但会要求你确认危险操作。直接告诉 AI 你想做什么就行，比如：「帮我查一下这台电脑的磁盘使用情况」。

Q: 数据安全吗？AI 会上传我的文件吗？

OpenClaw 本身不会上传你的文件。但 AI 对话内容会发送到 Anthropic 的 API（Claude），所以敏感信息最好不要让 AI 处理。AI 执行命令时也不会主动上传文件，除非你明确要求。

Q: 电脑关机了，AI 还能工作吗？

不能。OpenClaw 运行在你的电脑上，关机后 Gateway 停止，AI 就无法响应了。如果需要 24/7 可用，考虑部署到 VPS（云服务器）上，比如阿里云、腾讯云、DigitalOcean 等。

Q: 国内访问 Claude API 需要代理吗？

是的，Claude API 在中国大陆需要代理才能访问。可以配置系统代理，或者使用 Clash、V2Ray 等工具，确保 Node.js 进程能走代理。
设置方法：

export HTTPS_PROXY=http://127.0.0.1:7890
openclaw gateway restart
